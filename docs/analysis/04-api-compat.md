# 04 — FL API compatibility (stock KeyLab mkII script set)

_Reconstructed from the analyst's structured result (its report file could not be written). The 80-row call matrix is in `04-api-compat-matrix.md`. Machine-readable surface: `tests/fl_api_surface.json`, regenerated by `tests/gen_api_surface.py`. Known gap: the surface has no `ui`, `midi` or `utils` modules._

## Headline

Every FL API the stock KeyLab mkII set touches (80 functions + 11 midi constants, 295 sites, 12 files) exists with compatible arity in the official stubs, the current Image-Line manual (2 graph-editor functions undocumented), the FL 25.2.3 engine binary and the real midi.py; all 12 files compile clean on CPython 3.12 with -W error, and an arity-strict harness ran about 200 events / 1,804 API calls / 77 distinct functions with zero exceptions, so the missing-import, API-removal and Python-3.12 theories are refuted. The evidence instead points at FL 2026 host bugs on exactly the paths this script hammers (sysex-from-script crash fixed in 26.1.4, GlobalTransport crash/freeze fixed in 26.1.3, script-list crashes fixed in 26.1.3 and 26.1.5), a heavy MIDI-out load (241 sysex plus about 2.9 s of sleeps in OnInit, 22-24 sysex per OnIdle tick) and latent FL 2025 dynamic-mixer hazards; whether the user's build is affected is UNVERIFIED. Written: /home/delorenj/code/DeLoMIDI/tests/fl_api_surface.json (414 native functions, valid JSON, deterministic) and /home/delorenj/code/DeLoMIDI/tests/gen_api_surface.py; NOTE docs/analysis/04-api-compat.md was NOT written because the environment blocked report-file writes for subagents, so the full write-up is in these structured fields and the 80-row compatibility matrix is the report_path file (scratch data).

## Findings

### [HIGH] F-01 — FL 2026 MIDI-scripting crash/freeze bugs on this script's hot paths (host build UNVERIFIED)
`KeyLabmk2Dispatch.py:66`

send_to_device (KeyLabmk2Dispatch.py:65-66) routes every LCD/LED update through device.midiOutSysex; FL 26.1.4 (2026-08-06) fixes 'crash when processing sysex messages from a script' (22414) and 'mixer functions wrong with the current track' (22416). transport.globalTransport is called at KeyLabmk2Process.py:313,540,550,554,559,580,758 (758 is FakeMIDImsg, called from about 10 handlers); FL 26.1.3 (2026-07-24) fixes 'crash when using GlobalTransport commands' (22359) and 'freezes when MIDI scripts call functions in FL Studio' (22368), 26.1.2 fixes GlobalTransport delays (22298). 26.1.3 also fixes a startup crash reading the list of MIDI scripts (22367) and 'crash when using a MIDI controller' (22340); 26.1.4 'crash scanning midi devices' (22438); 26.1.5 (2026-08-18) 'crash finding MIDI scripts if the user data folder is cloud-based' (22496) plus device-scan crashes (22483, 22523). Latest listed build is 26.1.6 (2026-09-02). The same idioms (FPT_Punch fake message, FPT_Undo with event.pmeFlags) are used by Arturia's own 2024 mk3 script (KL3Process.py:1065), so they are not script bugs. Which build tom runs is unknown.

**Suggested fix:** Read the exact build on tom (Help > About). If below 2026.1.6, update FL first and re-test before touching any script; also check whether Documents is OneDrive-backed (22496).


### [MEDIUM] F-03 — FL 2025 dynamic mixer vs hard-coded 125/126 track limits and unguarded track-index math
`KeyLabmk2Process.py:56`

FL 2025.1 made mixer tracks dynamic (19548; betas 2025-04, RC1 2025-07-03, 25.1.1 2025-07-15) and added mixer.getTrackCount() (API 38, present in the 25.2.3 engine); mixer.trackCount() returns the live count including Master and Current; 19997 (invalid mixer track number crash) was fixed in the same release and since 2024.1 API errors raise proper exceptions (17588). The set hard-codes 125/126: KeyLabmk2Process.py:56 MAX_TRACKS=125, :412 bank limit, :602 'if track < 126', KeyLabmk2Return.py:20 NB_TRACK_MAX and :148. Bank math then calls mixer.isTrackSelected/isTrackMuted (KeyLabmk2Return.py:172-194, executed from OnIdle), mixer.setTrackNumber (KeyLabmk2Process.py:431), setTrackVolume/setTrackPan/getTrackPan (ArturiaCrossKeyboardKLmk2.py:12-56) on indexes that may not exist in a small project, with no try/except. Real-FL effect (raise vs ignore) is UNVERIFIED.

**Suggested fix:** Clamp bank/track indexes with mixer.getTrackCount() (mind Master/Current), wrap mixer calls in try/except, and stop polling 8 tracks per OnIdle when the bank is beyond the track count.


### [MEDIUM] F-04 — Unthrottled MIDI-out load and blocking OnInit (measured in the harness)
`KeyLabmk2Return.py:303`

OnInit sends 241 sysex and blocks about 2.92 s: KeyLabmk2Return.py:64 and :68 (192 x time.sleep(0.01)) plus :71 and :74 (2 x 0.5 s). OnIdle (device_KeyLabmkII.py:141-153) sends 22 sysex per tick, 24 with the channel rack or mixer focused: NotBlinkingLed (KeyLabmk2Return.py:303-324) resends 12 static LEDs every tick, SelectedChannel (:169-222) 8, plus Metronome/Loop/Solo/Mute. OnRefresh sends 19 because SequencerReturn rewrites all 16 pads, and OnRefresh ignores its flags argument (main:131). The stubs document OnIdle as roughly every 20 ms, so about 1,100 sysex/s of mostly static state, amplifying F-01. KeyLabmk2Process.py:293-295 (_hideAll) also calls channels.showEditor(i,0) for every channel on many button presses.

**Suggested fix:** Cache last-sent LED/LCD state and send only changes; remove NotBlinkingLed from OnIdle (send once in OnInit/OnRefresh); shorten or move the OnInit light show; honor OnRefresh flags.


### [LOW] F-05 — Index-space mismatch: global channels.channelNumber() fed to group-relative index parameters
`KeyLabmk2Process.py:437`

channels.channelNumber() returns the GLOBAL index while every channels.* and plugins.* index parameter is group-relative unless useGlobalIndex=True (manual: 'index is respecting channel groups'; API 33 added the flag). 27 channelNumber() sites, about 37 index arguments: ArturiaVCOL.py:50; KeyLabmk2Plugin.py:382,391,393,394; KeyLabmk2Process.py:322,394,399,437,465,470,565,573,745,746,749; KeyLabmk2Return.py:118,133,229,230; KeyLabmk2SeqParam.py:25 (alias used at :40-102, and setStepParameterByIndex/showGraphEditor pass useGlobalIndex=0 explicitly); device_Forward CCs Port 10 KEYLAB MKII.py:71,72. Correct only while the channel-rack filter is All. The stubs say selectedChannel 'replaces channelNumber'; Arturia's 2024 mk3 script uses selectedChannel() 45 times and main:63-64 here already does for the LCD.

**Suggested fix:** Replace channels.channelNumber() with channels.selectedChannel() everywhere an index feeds channels.*/plugins.*, or pass useGlobalIndex=True consistently.


### [LOW] F-06 — mixer.getCurrentTempo(1) treated as BPM but FL appears to return tempo x 1000 (UNVERIFIED)
`KeyLabmk2Return.py:285`

KeyLabmk2Return.py:285-286 computes tresh=(60/tempo)/4 and KeyLabmk2Navigation.py:203-206 prints the value followed by ' BPM'. Arturia's own mk3 code treats the value as tempo x 1000 (KL3Navigation.py:211-216 compares > 99000 and slices the first 2-3 digits) and MackieCU feeds it to getEventIDValueString(midi.REC_Tempo, ...). If so the LCD shows e.g. 120000 BPM and the step-blink threshold is 1000x too small. The manual only says asInt returns an int.

**Suggested fix:** Confirm the scale on tom (print mixer.getCurrentTempo(1) at 120 BPM) then divide by 1000.


### [LOW] F-07 — Out-of-range write to event.data2 (UNVERIFIED real-FL effect)
`KeyLabmk2Process.py:268`

KeyLabmk2Process.py:268 and :277 assign midi.MIDI_NOTEON (144) and midi.MIDI_NOTEOFF (128) to event.data2 (velocity, valid 0..127), apparently meaning status. The offline stub FlMidiMsg would raise ValueError (its own re-implementation, not FL ground truth); real FL's setter behavior is unknown. Present since 2021, affects drum-mode FPC pad notes only.

**Suggested fix:** Set event.status (or leave data2 as the velocity) and test drum-pad velocity on tom.


### [LOW] F-08 — Undocumented graph-editor functions; closeGraphEditor(1) passes a literal
`KeyLabmk2Process.py:738`

channels.closeGraphEditor (KeyLabmk2Process.py:738, KeyLabmk2SeqParam.py:33) and channels.updateGraphEditor (KeyLabmk2SeqParam.py:60,69,78,87,96,105) are absent from the manual; the stubs document them as ??? (closeGraphEditor(index, /) positional-only, 'since API 33?'). Both are in the 25.2.3 engine and used by Arturia's mk3 script. Passing literal 1 may target channel 1 rather than the active channel. FL 26.1.3 added a HW_Dirty_GraphEditor refresh flag (API 44) that could replace polling.

**Suggested fix:** Probe closeGraphEditor semantics in the Interpreter tab on tom before relying on it; guard with hasattr.


### [LOW] F-09 — setChannelPitch unit conflict between stubs (cents) and manual (semitones)
`device_Forward CCs Port 10 KEYLAB MKII.py:72`

device_Forward CCs Port 10 KEYLAB MKII.py:72 calls channels.setChannelPitch(ch, (data2-64)*(200/64), 1). Stubs: mode 1 = cents (+-200 cents, sane). Manual: pitchUnit 1 = semitones (+-200 semitones, clamped to range). UNVERIFIED which is right for FL 2025/2026.

**Suggested fix:** Test on tom; prefer mode 0 (factor of bend range, -1..1) which both sources agree on.


### [LOW] F-10 — patterns.jumpToPattern(pattern +- 1) is unbounded
`KeyLabmk2Process.py:447`

KeyLabmk2Process.py:447 and :455. Per the stubs, jumping to a non-existent pattern CREATES it, so 'next pattern' past the last pattern adds patterns; pattern-1 at pattern 1 targets index 0 (effect UNVERIFIED).

**Suggested fix:** Clamp to 1..patterns.patternMax().


### [LOW] F-11 — Native plugin-name literals and fixed parameter maps may be stale for FL 2026 (UNVERIFIED)
`KeyLabmk2Plugin.py:258`

KeyLabmk2Plugin.py:18,66,258,282,306 match ui.getFocusedPluginName() against fixed names with fixed parameter indexes. FL 2026 rebuilt FLEX from the ground up (changelog mentions 'Flex 2') and 26.1.6 references 'FL Key 2'. 'BASSDRUM' (:258) differs from mk3's 'BassDrum' (KL3Plugin.py:135, which itself is missing commas so entries concatenate). Parameter maps for rebuilt plugins may be wrong; this affects plugin-knob control only, not script startup.

**Suggested fix:** Log ui.getFocusedPluginName() for each native plugin on tom and re-derive the maps for FL 2026.


### [LOW] F-15 — Cross-script coupling: Forward script imports the main device script and re-runs init (UNVERIFIED)
`device_Forward CCs Port 10 KEYLAB MKII.py:27`

device_Forward CCs Port 10 KEYLAB MKII.py:19 imports device_KeyLabmkII as KL and :27 calls KL.init(), which rebuilds _mk2/_processor if FL shares one module namespace between the two device scripts (the smoke run shares sys.modules). 26.1 RC1 fixed 'TPythonSession.ThreadEnded' (22078) implying one Python session per script, but module isolation is unknown. OnInitAll (2025.1) exists for cross-script init ordering; its semantics are undocumented.

**Suggested fix:** Do not re-run init() from the Forward script; share state through a helper module or device.dispatch.


### [LOW] F-16 — No auto-detect metadata; FL 26.1.6 adds a new-controller notification (hardware ids UNVERIFIED)
`device_KeyLabmkII.py:1`

device_KeyLabmkII.py:1 has only '# name='; the mk3 script declares supportedHardwareIds (device_KL3.py:2). FL 26.1.6 (11872) shows a notification when a new controller connects with an option to enable it. The mkII hardware ids need the real device (device.getDeviceID()); Forward script line 2 has 'receiveFrom' equal to its own name with a trailing space.

**Suggested fix:** Read the id from tom and add '# supportedHardwareIds=' / '# supportedDevices='; strip the trailing space in receiveFrom.
